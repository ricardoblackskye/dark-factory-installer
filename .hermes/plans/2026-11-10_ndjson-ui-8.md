# Plan: #8 — WS6: NDJSON → UI step list

**Epic:** #1 (Dark Factory Installer) · **Issue:** [dark-factory-installer#8](https://github.com/ricardoblackskye/dark-factory-installer/issues/8)
**Branch:** `feat/8-ndjson-ui` (off `origin/main` @ `30ec683`)

## Context
The headless CLI (`df:sandbox-up`, from agent-eve) emits one JSON object per **stdout** line and puts
human prose on **stderr** (contract pinned by agent-eve #582 / #585 T2, defined in
`agent/lib/dark-factory/sandbox-events.ts`). #8 turns that NDJSON stream into a live, human-readable
step list in the WPF UI, maps terminal failure info to user-facing messages, and never parses stderr
prose for status.

### Exact event contract (from agent-eve `sandbox-events.ts`)
```
ProvisionStep  = "check"|"vendor"|"cluster"|"deploy"|"forward"|"proof"|"teardown"|"done"
ProvisionPhase = "start"|"success"|"failure"|"skip"
ProvisionEvent { ts: string; step: ProvisionStep; phase: ProvisionPhase; message: string; exitCode?: number }
```
`ts` is ISO-8601 UTC; `exitCode` is present **only** on the terminal `step:"done"` event. The terminal
event's `phase` is `success` (exitCode 0) or `failure` (otherwise).

### Contract nuance to design around (AC3/AC4/AC6)
agent-eve's #582 doc says the terminal `done` event *also* carries `problems[]` with a stable `code`
(e.g. `prerequisites-missing`, `prerequisites-mismatch`), but the **current emitter** only puts
`exitCode` + `phase` on `done` — the `problems` live in the internal `ProvisionResult`, not the NDJSON
stream. So #8:
- derives the success/failure **banner** from `exitCode` / `done.phase` today (AC3) — the reliable signal;
- maps `problems[].code` to an actionable message **when present** (AC4);
- **tolerates** the documented shape and validates against agent-eve's schema once #612 ships (AC6).

### Problem codes (#585 T1 — `ProvisionProblemCode`)
`prerequisites-missing` (exit 10) · `prerequisites-mismatch` (15) · `artifact-unresolvable` (11) ·
`cluster-unreachable` (12) · `proof-failed` (13) · `teardown-failed` (14) · `internal` (1).
Each `ProvisionProblem` carries `{ code, subject, fix }`; the code is for machines, prose for operators.

## Decision (confirmed direction)
#8 implements the parser + UI + an **inline** mapping for the documented codes. The broader message
catalog is owned by **#10** (open) — #8 defines the seam (`ProblemMessageMapper`) and wires the seven
codes now; #10 may later centralise/expand it. Parse by `code`, never string-match prose.

## Tasks (TDD, AC1–AC6)

- **T1 — Event models (Domain).** `ProvisionStep` (enum), `ProvisionPhase` (enum), `ProvisionProblem`
  (`Code`, `Subject?`, `Fix?`), `ProvisionEvent` (`Ts`, `Step`, `Phase`, `Message`, `ExitCode?`,
  `Problems`), and `ProvisionProblemCode` (enum of the seven). Pure, no dependencies.
- **T2 — `NdjsonEventParser` (Orchestration).** `ParseLine(string) => ProvisionEvent?`: a malformed /
  non-JSON line returns `null` and is handed to a logger (AC1) — never throws. Unknown `step` / `phase`
  / extra fields are tolerated (AC6). Unit-tested with a fake line source.
- **T3 — Streaming seam.** Consume the CLI stdout **line-by-line** so the UI updates as events arrive
  (AC2). #7 ("streaming provision") already runs `df:sandbox-up`; confirm its runner shape during
  implementation and, if it returns a completed `ProcessResult`, add `IStreamingProcessRunner` (per-line
  callback / `IObservable<ProcessLine>`) as an injectable adapter — same seam style as #4/#5/#7. stderr
  lines flow to the log view (AC5).
- **T4 — WPF UI.** A `ProvisionViewModel` + `MainWindow` additions: a live step list bound to
  `ObservableCollection<StepRow>` keyed by `step` (phase icon + message, AC2); the `done` event sets a
  success/failure **banner** from `exitCode`/`phase` (AC3); `problems[].code` renders an actionable
  message (AC4); stderr prose is captured into a **log view** (AC5, never parsed for status).
- **T5 — `ProblemMessageMapper` (Orchestration).** Maps each `ProvisionProblemCode` → a clear,
  user-facing message (using the code, not prose matching); the seven documented codes wired now, the
  seam left open for #10 to own the catalog.
- **T6 — Tests (xUnit, fakes).** `NdjsonEventParserTests` (malformed → null/logged, skip phase,
  `done`+exitCode, `problems` when present, unknown-field tolerance — AC1/AC6); `ProblemMessageMapperTests`
  (every code maps, no prose matching — AC4); `ProvisionViewModelTests` (events update the step list live,
  `done` sets banner, skip treated as satisfied — AC2/AC3); an optional drift guard pinning agent-eve's
  `gui-contract` event shape (AC6).
